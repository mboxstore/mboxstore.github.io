For Developers

Publish your app on MBOX Store — reach Android users who can't rely on Google Play, with verified distribution and built-in payments.

Why publish here

Reach

Your app is listed in the store catalog and discoverable by every MBOX Store user, with in-app updates delivered automatically.

Trust

Every listing is verified — package name, signing certificate and SHA-256 hash are checked before install. Users know your app is the genuine one.

Monetization built in

Sell your app or offer in-app purchases through MBOX Pay — users pay with Telegram Stars, prepaid Balance or USDT, no payment integration of your own needed.

90% / 10%

You keep 90% of every sale. MBOX Store takes a flat 10% fee on paid apps and in-app purchases. Listing is free.

How listing works

  1. Open the Developer Console in our Telegram bot @mboxstoreappbot and register as a developer.
  2. Submit your APK through the console — it must be signed with your own release key.
  3. Your submission is screened (package, version, permissions, certificate, VirusTotal) and reviewed against the listing rules below.
  4. Updates: submit the new APK the same way — it must keep the same package name, the same signing certificate and a higher version code.

Listing rules

  • Original apps only — you must own the app or have the right to distribute it.
  • No modified, repacked or cracked versions of other developers' apps.
  • No apps that imitate banks, payment services or other brands.
  • No online-loan apps and no unlicensed gambling apps.
  • Permissions must match what the app actually does.

In-app purchases — the developer kit

No SDK and no store update needed. Your app opens MBOX Store for the purchase, the buyer receives a license key, and your app verifies that key against one API call.

How a purchase flows

  1. Your app shows a Buy button. Tapping it opens MBOX Store on your app's page.
  2. The buyer pays with Telegram Stars, Balance or USDT (TON). Prices come from your catalog entry — never from the app — so they cannot be tampered with.
  3. As soon as the order is paid, the store bot DMs the buyer a license key like PRO-7K2Q9P-4X8MND. The key also appears in the buyer's order history inside MBOX Store.
  4. The buyer pastes the key into your app. Your app calls the verify API once, caches the result, and unlocks the product.

Listing an IAP product

IAP products live in your app's catalog entry. Ask the store team to add an iap list like this:

"iap": [
  {
    "id": "pro_unlock",
    "label": "Pro Unlock",
    "priceStars": 250,
    "priceUsdt": 4.5,
    "keyDelivery": true,
    "keyPrefix": "PRO",
    "durationDays": 0
  }
]
FieldMeaning
idStable product id. Never reuse an id for a different product.
labelShown to the buyer at checkout and in the key DM.
priceStars / priceUsdtPrice per rail. Omit or 0 = not sold on that rail.
keyDeliverytrue = the store issues a license key for this product.
keyPrefixKey prefix, up to 6 letters/digits (default MBX).
durationDays0 = the key never expires. 30 = a 30-day key (subscriptions).

Verify API

POST https://store.mboxcommunity.org/pay/iap/verify
Content-Type: application/json

{ "key": "PRO-7K2Q9P-4X8MND" }

The key is the credential — no API key or account is needed. Input is case-insensitive and surrounding spaces are ignored.

Active key (HTTP 200):

{ "ok": true, "status": "active", "package": "com.example.app",
  "productId": "pro_unlock", "expiresAt": 0 }

expiresAt is a Unix time in milliseconds; 0 means no expiry. Not active (HTTP 200): { "ok": false, "error": "not_found" }

errorMeaningWhat your app should do
not_foundNo such key was ever issued.Ask the user to check the key and re-enter it.
expiredThe key's duration has run out (expiresAt is included).Offer renewal — the user buys again in MBOX Store and gets a new key.
revokedThe key was revoked (refund or abuse).Keep the product locked.
bad key (HTTP 400)Empty/missing key field.Client bug — always send a non-empty key.

Also check that package and productId in an active answer match your app and the product being unlocked. Verify when the user enters the key, cache the result, and for expiring keys re-verify at most once a day. If the device is offline, keep the last known state until the cached expiry — never lock a paying user out over a network hiccup.

Kotlin sample — MboxIap.kt

A dependency-free client (HttpURLConnection + Android's built-in JSON) with openStore() and verifyKey(). Copy it into your project:

package com.example.mboxiap

import android.content.Context
import android.content.Intent
import android.net.Uri
import org.json.JSONObject
import java.net.HttpURLConnection
import java.net.URL
import kotlin.concurrent.thread

/**
 * MBOX Store in-app purchase client (license-key flow).
 *
 * No dependencies beyond the Android framework. See DEVELOPER-IAP.md.
 *
 * Flow:
 *  1. Call openStore() from your Buy button.
 *  2. The buyer pays in MBOX Store and receives a license key from
 *     the store bot (and in their order history).
 *  3. The buyer pastes the key into your app; call verifyKey() and
 *     unlock when the result is Active for YOUR package + product.
 */
object MboxIap {

    private const val API_BASE = "https://store.mboxcommunity.org"
    private const val STORE_PACKAGE = "com.mbox.store"

    sealed class Result {
        /** Key is good. expiresAtMs == 0L means it never expires. */
        data class Active(val expiresAtMs: Long) : Result()
        object NotFound : Result()
        data class Expired(val expiresAtMs: Long) : Result()
        object Revoked : Result()
        /** Wrong package/product for this key, or a network problem. */
        data class Error(val message: String) : Result()
    }

    /**
     * Opens MBOX Store so the user can buy. Falls back to your app's
     * web page when the store app is not installed.
     */
    fun openStore(context: Context, yourPackage: String) {
        val launch = context.packageManager.getLaunchIntentForPackage(STORE_PACKAGE)
        if (launch != null) {
            context.startActivity(launch)
        } else {
            val web = Intent(
                Intent.ACTION_VIEW,
                Uri.parse("https://mboxstore.github.io/app/$yourPackage")
            )
            context.startActivity(web)
        }
    }

    /**
     * Verifies a license key for [expectedPackage] + [expectedProductId].
     * Runs the network call on a background thread; [callback] is
     * invoked on that same background thread — hop to the UI thread
     * inside your callback if you touch views.
     */
    fun verifyKey(
        key: String,
        expectedPackage: String,
        expectedProductId: String,
        callback: (Result) -> Unit
    ) {
        thread {
            val result = try {
                val conn = URL("$API_BASE/pay/iap/verify").openConnection()
                    as HttpURLConnection
                conn.requestMethod = "POST"
                conn.setRequestProperty("Content-Type", "application/json")
                conn.connectTimeout = 15_000
                conn.readTimeout = 15_000
                conn.doOutput = true
                val body = JSONObject().put("key", key.trim()).toString()
                conn.outputStream.use { it.write(body.toByteArray(Charsets.UTF_8)) }
                val text = (if (conn.responseCode in 200..299)
                    conn.inputStream else conn.errorStream)
                    ?.bufferedReader()?.use { it.readText() } ?: "{}"
                parse(JSONObject(text), expectedPackage, expectedProductId)
            } catch (e: Exception) {
                Result.Error(e.message ?: "network error")
            }
            callback(result)
        }
    }

    private fun parse(
        json: JSONObject,
        expectedPackage: String,
        expectedProductId: String
    ): Result {
        if (!json.optBoolean("ok")) {
            return when (json.optString("error")) {
                "not_found" -> Result.NotFound
                "expired" -> Result.Expired(json.optLong("expiresAt"))
                "revoked" -> Result.Revoked
                else -> Result.Error(json.optString("error", "unknown error"))
            }
        }
        // A key only unlocks the product it was issued for — never
        // accept a key belonging to another app or product.
        if (json.optString("package") != expectedPackage ||
            json.optString("productId") != expectedProductId
        ) {
            return Result.Error("key is for a different product")
        }
        return Result.Active(json.optLong("expiresAt"))
    }
}

Fees and payouts

  • Store fee: 10% of paid app and IAP sales; you receive 90%. Free apps and free products are never charged.
  • Set your payout TON wallet in the Developer Console — the same wallet receives app-sale and IAP payouts.
  • A refunded order's key is revoked by the store team; a revoked key stops verifying immediately.
  • Keys are issued for paid orders only, at most one per order, automatically — there is nothing for you to call at purchase time.
